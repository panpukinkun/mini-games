以下はGeminiで生成したゲーム開発のための設計図になります。ただ、OpenCodeでそれをちゃんと把握してできるかどうかというところはわからないので、これをまずは渡しますので、あなた自身でもよく考えてみてください。

そして、これを作る際に注意してほしいこととしては、もうすでに「パンティンくんの遊び部屋」というプラットフォームがありますので、そのことも考えて、そこで動かせるような形に出力することがゴールになります。


なので、Geminiでの設計図をそのまま使うかどうか、私は判断しかねるので、一番良い形で、あなたがそれらをまとめてやってほしいです。以上。

ブラウザベースのボンバーマンゲームをopencodeで実装するための詳細な設計図です。技術選定からアーキテクチャ、コンポーネント構成、データフロー、そして開発時のボトルネック回避策まで網羅しています。そのままopencodeに渡すためのプロンプトや仕様書としてご利用いただけます。ブラウザベース ボンバーマンゲーム 設計仕様書1. プロジェクト概要と技術スタック1.1 概要PC、タブレット、スマートフォンすべてのデバイスで快適に動作する、リアルタイム対戦（またはCPU対戦）可能なブラウザベースのボンバーマン風ゲーム。1.2 技術スタック * コア言語: TypeScript (型安全性、メンテナンス性の担保) * レンダリング: HTML5 Canvas API (軽量、マルチデバイスで安定した描画パフォーマンス) * 状態管理 / ゲームループ: RequestAnimationFrameベースのカスタムゲームループ * UI / スタイル: Tailwind CSS (レスポンシブ対応、モダンなUI) * ビルドツール: Vite (高速な開発サーバーとバンドル) * サウンド: Web Audio API (外部ライブラリ依存なしでの効果音・BGM生成または軽量音声ファイル再生)2. 画面デザイン・レイアウト設計2.1 レスポンシブUI構成画面全体を flex-col または CSS Grid で上下（または左右）に分割し、どの画面サイズでもゲームフィールドが必ず視認できるようにする。+-------------------------------------------------+| ヘッダー: スコア / 残機 / タイ残時間 / ポーズボタン |+-------------------------------------------------+|                                                 ||               ゲームフィールド                    ||           (Canvas / 13x11 グリッド等)            ||                                                 |+-------------------------------------------------+| 操作パネル (タブレット・スマホ表示時のみ有効)       ||    [↑]           [爆弾設置]                      || [←][↓][→]                                       |+-------------------------------------------------+
2.2 デバイス別表示最適化 * PC: キーボード操作（矢印キー / WASD + スペースキー）を主軸。操作パネルは非表示。 * タブレット・スマホ: グリッドの下部に半透明のバーチャルパッド（方向キーとボンプボタン）を常時オーバーレイ表示、または画面下部に固定配置。タッチ操作の誤作動を防ぐため、touch-action: none を適用。3. 機能設計3.1 ゲームモード * シングルプレイ: プレイヤー1人 vs CPUプレイヤー（3体など） * ステージ構成:   * 固定サイズのグリッドマップ（例: 幅13 × 高さ11）   * 外周：破壊不可ブロック   * 内部：格子状の破壊不可ブロック ＋ ランダム配置の破壊可能ブロック（ソフトブロック）3.2 コアゲームメカニクス * 移動処理:   * グリッドスナップ（マス目単位の移動）を基本としつつ、スムーズな移動のために座標ベースの当たり判定（AABB: Axis-Aligned Bounding Box）を採用。   * 角に引っかかりづらくするための「コーナー補正（スライド処理）」を実装する。 * 爆弾システム:   * プレイヤーごとの設置上限数（初期値1）と火力（初期値1マス）を管理。   * 爆弾は設置から一定時間（例: 3秒）経過後に十字方向に爆風を発生させる。   * 爆風はソフトブロックを破壊し、他の爆弾に触れると誘爆する。 * パワーアップアイテム（ソフトブロック破壊時に確率で出現）:   * 火力アップ (Fire): 爆風の射程が+1   * 爆弾数アップ (Bomb): 同時設置数が+1   * スピードアップ (Speed): 移動速度が上昇 * 勝敗判定:   * プレイヤーが爆風に巻き込まれる、または敵に接触すると残り残機減少（またはゲームオーバー）。   * 最後の一人（またはチーム）になるまで生存したプレイヤーの勝利。4. アーキテクチャとファイル構成opencodeに生成させる際の見取り図となるファイル構成案。src/├── main.ts                  # エントリーポイント├── types/│   └── game.ts              # 型定義 (Player, Bomb, Block, Item等)├── constants/│   └── gameConfig.ts        # マップサイズ、速度、タイマー等の定数├── core/│   ├── GameLoop.ts          # requestAnimationFrame 管理│   └── InputHandler.ts      # キーボード・タッチ入力の統合管理├── entities/│   ├── Player.ts            # プレイヤー / CPUの移動と状態│   ├── Bomb.ts              # 爆弾のタイマーと爆風判定│   └── MapManager.ts        # マップの生成、ブロック破壊、アイテム管理├── audio/│   └── SoundManager.ts      # Web Audio API による効果音管理└── ui/    ├── HUD.ts               # スコア、残り時間の描画    └── VirtualPad.ts        # スマホ用タッチコントローラー
5. ボトルネック回避と実装時の注意点開発時・実行時に陥りやすい問題点と、事前に講じるべき対策。5.1 モバイル端末におけるタッチ操作の遅延とスクロール問題 * 問題: スマホで画面をタッチした際にデフォルトのズームやスクロールが発動し、操作がカクつく。 * 対策: CSSで touch-action: none; および user-select: none; をCanvasやコントロール要素に完全に適用する。また、touchstart / touchend イベントのデフォルト挙動を preventDefault() で抑制する。5.2 当たり判定（コリジョン）のすり抜け・角抜け問題 * 問題: 簡易的なグリッド判定だけを実装すると、壁の角にぶつかったときに動きが完全に停止するか、壁をすり抜けてしまう。 * 対策:   * 移動処理を「X軸方向の移動＋衝突判定」と「Y軸方向の移動＋衝突判定」に分離して処理する。   * キャラクターの当たり判定ボックスを実際の見た目よりわずかに小さく（スリムに）設定し、角に微小な余裕（コーナースライド）を持たせる。5.3 ゲームループのデルタタイム（Delta Time）制御の欠如 * 問題: 端末のフレームレート（60Hz、120Hzなど）によってゲームの移動速度や爆弾のタイマーが変わってしまう。 * 対策: requestAnimationFrame の経過時間（\Delta t）を毎回算出し、すべての移動量やタイマー計算に掛けることで、どの端末でも同じ速度で動作するように保証する。5.4 メモリリークとイベントリスナーの重複 * 問題: 画面遷移やリスタート時にキーボード・タッチイベントのリスナーが残存し、二重に反応する。 * 対策: クラス設計（またはクリーンアップ関数）を徹底し、ゲーム終了時やインスタンス破棄時に必ず removeEventListener を実行する構造にする。6. opencodeへの指示用プロンプト（コピペ用）以下のブロックをそのままコピーしてopencodeに入力することで、実装コードの生成をスムーズに開始できます。TypeScriptとVite、HTML5 Canvasを使用して、ブラウザベースのボンバーマンゲームを構築してください。PCとモバイル（タブレット・スマホ）の両方で快適に遊べるように設計してください。
以下の要件を満たしてください：1. ファイル構成は、types、core（GameLoop, InputHandler）、entities（Player, Bomb, MapManager）、uiに綺麗に分離すること。2. モバイル対応として、画面下部にタッチ操作用のバーチャルパッド（十字キーと爆弾ボタン）を配置し、touch-action: none でスクロールやズームを防止すること。3. 当たり判定は角抜けや引っかかりを防ぐ頑健なAABBコリジョンとコーナースライドを実装すること。4. フレームレート依存を防ぐため、すべての移動・タイマー計算にDelta Timeを適用すること。5. ソフトブロック破壊時のランダムアイテム生成（火力アップ、爆弾数アップ、スピードアップ）を含めること。
まずはプロジェクトの全体像と主要な型定義（types/game.ts）、およびコアとなるゲームループ・マップ管理のコードから段階的に作成してください。
